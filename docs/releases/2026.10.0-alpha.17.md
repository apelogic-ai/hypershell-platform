# Steward platform 2026.10.0-alpha.17

A pre-release of the Steward platform BOM that moves Steward to **0.3.25**
(from 0.3.21), steward-run to **0.8.3** (from 0.8.2), and mcp-gw to **0.7.2**
(from 0.7.1). github-oidc-exchange remains **0.7.6**, and every third-party
dependency is unchanged. It remains an alpha: the governed profile, which
runs agents and would install mcp-gw, is not implemented yet.

Read the upgrade notes first. Steward adds an attested Claude Code reference
runtime and opt-in dependency charts without a database migration. steward-run
adds a default-off image source while keeping digest pinning as the default.
MCP-GW adds optional callback routing whose default is unchanged.

## Upgrade notes

Steward owns its procedure: the
[0.3.25 upgrade and rollback notes](https://github.com/apelogic-ai/steward/blob/v0.3.25/CHANGELOG.md#upgrade-and-rollback)
and
[installation guide](https://github.com/apelogic-ai/steward/blob/v0.3.25/docs/installation/installation-guide.md).
The other products own their
[steward-run 0.8.3 release notes](https://github.com/apelogic-ai/steward-run/releases/tag/v0.8.3)
and MCP-GW
[0.7.2 upgrade notes](https://github.com/apelogic-ai/mcp-gw/blob/v0.7.2/CHANGELOG.md#072---2026-10-23).
What follows is what those releases mean for a combined installation.

- **Deploy Steward as one release unit.** Roll the 0.3.25 chart and every
  enabled component image together. No database migration is required from
  0.3.21, and the standalone chart keeps its prior default rendering.
- **Mirror the new runtime before enabling it.** The Claude Code reference
  runtime is a new first-party BOM image. Mirror it by digest and update the
  `claude-code-v1` execution binding to that digest before activation.
- **Adopt dependency charts separately.** The new Steward bundle and governed
  dependency charts are opt-in release artifacts. Supply their documented
  namespaces, existing Secret references, permissions and Gateway settings
  before installing them. This platform release does not install them.
- **Upgrade steward-run as one signed set.** Move the action and workflow
  commit, runner image, chart and any vendored workflow together from the
  signed manifest. Existing values using the direct digest source need no
  change. The repository-and-tag source is default-off, and digest pinning
  remains the default.
- **Keep MCP-GW callback routing off unless reviewed.** Version 0.7.2 can add
  exact Gateway API callback routes for enabled wrappers. The option is off by
  default; no migration or new required value is needed.
- **Keep unchanged components unchanged.** github-oidc-exchange stays at
  0.7.6. No dependency version or implemented profile membership changes.

### Rollback

- Before rolling Steward back to 0.3.21, stop new Claude Code Tasks and let
  active Tasks finish, then restore execution bindings to a runtime supported
  by 0.3.21. Remove dependency charts only when they were adopted solely for
  0.3.25, and restore their prior ownership. No database rollback is required.
- Restore steward-run 0.8.2 only as one manifest-defined action, workflow,
  image, chart and vendored-workflow set. The rollback removes the optional
  repository-and-tag source and restores the HTTP client version affected by
  the advisory fixed in 0.8.3.
- Disable MCP-GW callback routing before restoring 0.7.1. No database,
  credential or Secret-format rollback is required.

For the **core, task-auth and browser-admin profiles in this BOM**, the new
Steward dependency charts, Claude Code execution binding, steward-run image
source and MCP-GW callback routes remain absent or disabled. Regeneration
changes product coordinates and platform-version references; it does not add
mcp-gw, an agent catalog, provider origins or Task execution.

[`bom/bom.json`](../../bom/bom.json) at this version is authoritative. The
tables below abbreviate digests to 12 hex characters for reading; install from
the full digests in the BOM, never from tags.

## Product changes

### Steward 0.3.25

Steward adds a hardened linux/amd64 Claude Code reference runtime with an
immutable digest, SBOM, vulnerability report and provenance. Its launcher
accepts only the deployment-provided compatible inference URL and sandbox
placeholder, disables updates and nonessential traffic, removes alternate
authentication paths, and refuses startup when required settings are missing
or changed.

The release also publishes separately installable charts for governed
dependencies and a bundle chart. They are opt-in, create no Namespace, take
existing Secret references rather than inline secret material, and pin their
rendered images. Security maintenance updates Tokio for RUSTSEC-2026-0386.
The 0.3.22 through 0.3.24 tags did not complete publication; 0.3.25 is the
complete release that carries their intended content.

### steward-run 0.8.3

The ARC chart adds top-level repository, tag, digest and `requireDigest`
values for delivery platforms that promote images by tag. The source is
default-off. `requireDigest` defaults to true, exact lowercase SHA-256 digests
remain the default, and refusal checks reject incomplete values, mutable
channel tags, placeholder digests and simultaneous image sources.

The action bundle also updates its exact HTTP client dependency to the first
version fixed for the release's cited security advisory. The checked-in bundle
and lockfile were regenerated and the production high-severity dependency
audit is clean.

### MCP-GW 0.7.2

MCP-GW lets an opt-in chart setting add exact Gateway API callback routes for
enabled wrappers without publishing their private connection lifecycle paths.
The option remains off by default, so existing chart renders are unchanged.

### github-oidc-exchange 0.7.6

Unchanged from alpha.16.

## Upgrading from 2026.10.0-alpha.16

1. Read and satisfy the upgrade notes above. No database migration is added.
2. Regenerate from unchanged platform values. Review the Steward,
   steward-run and MCP-GW pins and platform tag references. No implemented
   profile gains mcp-gw or enables a new optional product surface.
3. Copy or rebuild the changed product artifacts for a registry mirror or
   built-artifacts lock. Include the new Claude Code reference runtime even if
   no implemented profile activates it.
4. Apply with `helmfile --environment <env> --kube-context <context> sync`, or
   let Flux reconcile the regenerated objects. Wait for every old enabled
   product pod to leave before enabling any new release surface.
5. Keep the new reference runtime, governed dependency charts, optional ARC
   image source and MCP-GW callback routes disabled until their product-owned
   prerequisites and refusal tests have been reviewed.

An alpha.16 built lock is refused because its Steward version, commit and
image set do not match this BOM. Existing platform-values files still validate
unchanged.

## What this repository verifies

The local and CI gates validate the BOM and schemas, resolve every pinned
digest, verify product attestations and signatures, regenerate every example,
render the pinned charts, exercise built mode and Helm hooks, and compare Flux
output with the generator. The cluster jobs install the core, task-auth and
browser-admin profiles on the tested Kubernetes versions.

This release does **not** install or exercise mcp-gw, the new Steward
dependency charts, Claude Code Tasks, governed Tasks, the sandbox helper or
the repository-and-tag ARC image source. Those remain outside the implemented
profiles. Their BOM pins are supply-chain verified, not an end-to-end
compatibility claim for an enabled optional surface.
