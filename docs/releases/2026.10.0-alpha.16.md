# Steward platform 2026.10.0-alpha.16

A pre-release of the Steward platform BOM that moves Steward to **0.3.21**
(from 0.3.19, including 0.3.20), github-oidc-exchange to **0.7.6** (from
0.7.5), steward-run to **0.8.2** (from 0.8.1), and mcp-gw to **0.7.1** (from
0.6.0, including 0.6.1, 0.6.2 and 0.7.0). Every third-party dependency is
unchanged. It remains an alpha: the governed profile, which runs agents and
would install mcp-gw, is not implemented yet.

Read the upgrade notes first. Steward adds migrations 0072 through 0075 and
two rollback boundaries. github-oidc-exchange adds default-off issuer and
workload profiles. steward-run removes a critically vulnerable unused package
chain. MCP-GW adds default-off governed command and remote-shell surfaces.

## Upgrade notes

Steward owns its procedure: the *Upgrade and rollback* sections for
[0.3.21](https://github.com/apelogic-ai/steward/blob/v0.3.21/CHANGELOG.md#upgrade-and-rollback)
and
[0.3.20](https://github.com/apelogic-ai/steward/blob/v0.3.21/CHANGELOG.md#upgrade-and-rollback-1),
and the
[installation guide](https://github.com/apelogic-ai/steward/blob/v0.3.21/docs/installation/installation-guide.md).
The other products own their
[github-oidc-exchange 0.7.6 guide](https://github.com/apelogic-ai/github-oidc-exchange/blob/v0.7.6/docs/upgrade-v0.7.6.md),
[steward-run 0.8.2 release notes](https://github.com/apelogic-ai/steward-run/releases/tag/v0.8.2),
and MCP-GW
[0.7.1 through 0.6.1 upgrade notes](https://github.com/apelogic-ai/mcp-gw/blob/v0.7.1/CHANGELOG.md#071---2026-10-22).
What follows is what those releases mean for a combined installation.

- **Back up Steward's database.** Apply additive migrations 0072, 0073, 0074
  and 0075 before the new Steward processes serve. Migration 0072 admits the
  new `api` Task origin; 0073 adds nullable immutable caller-reference
  context; 0074 adds owner-scoped personal-agent, turn, message and event
  tables; and 0075 bounds interrupted-turn retries. None rewrites historical
  rows.
- **Deploy Steward as one release unit.** Roll the 0.3.21 chart and every
  enabled Steward component image together. Configure the trigger receiver,
  external callers, personal agents, user access-token issuers, public trust
  material or route timeouts only when enabling those opt-in surfaces.
- **Keep the current Steward prerequisites.** Governed installations still
  set the installed SPIRE class, choose exactly one owner for sandbox
  registration, authorize each Git source and configure intended Envelope
  templates before browser Runs. Existing chart values otherwise retain their
  previous rendering.
- **Leave new exchange profiles off unless reviewed.** The 0.7.6 defaults keep
  GitHub v5/v6 exchange and OpenShell workload role bindings unchanged.
  Generic OIDC, pure-service workload Task bindings, tag-only images and a
  chart-owned public GitHub policy ConfigMap each require an explicit choice.
- **Upgrade steward-run as one signed set.** Move the action and workflow
  commit, runner image, chart and any vendored workflow together. Version
  0.8.2 removes the unused `python3-jwt` reverse-dependency chain that carried
  CVE-2026-102267 and CVE-2026-102268.
- **Keep MCP-GW additions disabled by default.** The governed CLI, shared
  Gateway profile, sandbox helper and remote shell are not enabled by this
  platform BOM. Enabling them requires their full release-defined issuer,
  identity, route, Secret, grant, timeout and target-binding inputs. The
  sandbox helper accepts its endpoint and credential only from the documented
  environment and must be installed from an architecture-specific verified
  release archive.
- **Use the 0.7.1 helper selector when needed.** A runtime that does not
  preserve the helper's invocation name uses a leading
  `--operation kubectl` or `--operation remote-shell`. Missing, late, unknown
  or conflicting selectors fail before a request.

### Rollback

- Keep migrations 0072 through 0075 and their historical rows when rolling
  Steward back.
- Before rolling Steward below 0.3.20, stop Task submission and prove that no
  stored Task has the `api` origin. Version 0.3.19 cannot read that immutable
  value. If any such row exists, restore the pre-upgrade database or keep
  0.3.20-or-later API readers. The nullable caller-reference column may remain.
- Before rolling Steward from 0.3.21 to 0.3.20, stop new personal-agent
  messages and let active turns finish. Remove 0.3.21-only chart values and
  restore externally managed public ConfigMaps if the 0.3.21 chart created
  them. Migrations 0074 and 0075 may remain because 0.3.20 ignores the tables.
- Before rolling github-oidc-exchange to 0.7.5, disable generic OIDC and
  workload `task` bindings. Restore the application, chart and policy
  references together; preserve signing-key overlap, policy objects and
  replay Leases until token and rollback windows expire.
- Restore steward-run 0.8.1 only as one manifest-defined action, workflow,
  image, chart and vendored-workflow set. That rollback reintroduces the
  critically vulnerable `python3-jwt` package and removes successful replay
  and explicit bundled-caller support.
- Disable and remove the governed CLI, shared-Gateway-only values, remote
  shell and sandbox-helper integration before rolling MCP-GW to 0.6.0. MCP-GW
  0.6.1 through 0.7.1 add no database migration, OAuth reconnect, provider
  reauthorization, Secret-format change or new required value.

For the **core, task-auth and browser-admin profiles in this BOM**, the
trigger receiver, personal agents, new exchange profiles, governed CLI,
shared-Gateway MCP route, sandbox helper and remote shell remain absent.
Regeneration changes product coordinates and platform-version references; it
does not add mcp-gw, an agent catalog, provider origins, external callers or
Task execution.

[`bom/bom.json`](../../bom/bom.json) at this version is authoritative. The
tables below abbreviate digests to 12 hex characters for reading; install from
the full digests in the BOM, never from tags.

The new `trigger-receiver`, `governed-cli` and `remote-shell` pins are read by
the BOM provenance verifier and whole-platform mirror list. They keep future
trigger and governed assemblies from floating or omitting their first-party
runtimes. The sandbox helper is a release binary rather than an OCI product
image. The GitHub MCP Server mirror is third-party and follows its upstream
signature plus digest-equality trust path. Neither belongs in this BOM image
set.

## Product changes

### Steward 0.3.20 and 0.3.21

0.3.20 adds governed external Run API callers and signed Jira webhook
Triggers. The isolated receiver validates signatures and filters, checks a
read-only Envelope, starts Tasks idempotently, polls within a bounded deadline
and cleans up completed deliveries. Run views can expose bounded caller
context, validated partial output and requested bounded failure diagnostics.

0.3.21 adds owner-scoped personal agents with durable conversations and
resumable updates. It accepts carefully scoped user access tokens from
configured issuers, advertises reviewed Kubernetes command and remote-shell
grants, and adds opt-in component repositories/tags, public trust material and
HTTPRoute timeouts. Security maintenance refreshes the web trust roots and
pins the current LiteLLM image by digest.

### github-oidc-exchange 0.7.6

The exchange adds default-off generic OIDC profiles with exact configured
issuers, audiences and claim bindings, plus pure-service Task tokens for exact
Kubernetes workload identities. It also adds explicit tag-only image and
chart-owned public policy modes. Existing GitHub v5/v6 exchange stays the
default. Certificate-validation dependencies and bundled trust roots reject
distrusted emSign paths.

### steward-run 0.8.2

The runner removes the unused `python3-jwt` dependency chain and verifies its
absence in both native images. It accepts Steward's HTTP 200 response for a
successful idempotent replay and adds explicit idempotency-key, workspace and
outputs-file flags for bundled callers outside GitHub Actions.

### MCP-GW 0.6.1 through 0.7.1

0.6.1 adds the default-off governed CLI, governed remote-shell server code,
generic OAuth disconnect, safer session reuse and additional audit events.
0.6.2 adds the opt-in shared-Gateway chart profile and optional hiding of
provider tools until connection. 0.7.0 publishes the sandbox helper and wires
the default-off remote-shell image, workload identity, bindings and route into
the chart. 0.7.1 makes the helper's operation explicit when invocation names
are canonicalized. The release adds no database migration and keeps every new
chart surface opt-in.

## Upgrading from 2026.10.0-alpha.15

1. Read and satisfy the upgrade notes above. Back up the Steward database.
2. Regenerate from unchanged platform values. Review the four product chart
   and image pins and platform tag references. No implemented profile gains an
   mcp-gw release or enables a new optional product surface.
3. Copy or rebuild the changed product artifacts for a registry mirror or
   built-artifacts lock. The whole-platform mirror list now also includes the
   new first-party `trigger-receiver`, `governed-cli` and `remote-shell`
   images.
4. Apply with `helmfile --environment <env> --kube-context <context> sync`, or
   let Flux reconcile the regenerated objects. Wait for every old enabled
   product pod to leave before enabling any new release surface.
5. Keep generic OIDC, workload Task bindings, trigger receivers, personal
   agents, governed CLI, shared-Gateway MCP routes, sandbox helper and remote
   shell disabled unless their product-specific prerequisites and refusal
   tests have been reviewed separately.

An alpha.15 built lock is refused because its product versions and commits do
not match this BOM. Existing platform-values files still validate unchanged.

## What this repository verifies

The local and CI gates validate the BOM and schemas, resolve every pinned
digest, verify product attestations and signatures, regenerate every example,
render the pinned charts, exercise built mode and Helm hooks, and compare Flux
output with the generator. The cluster jobs install the core, task-auth and
browser-admin profiles on the tested Kubernetes versions and apply Steward's
migrations, including 0072 through 0075.

This release does **not** install or exercise mcp-gw, the trigger receiver,
external callers, personal agents, generic OIDC, workload Task bindings,
governed Tasks, the sandbox helper or remote shell. Those remain outside the
implemented profiles. Their BOM pins are supply-chain verified, not an
end-to-end compatibility claim for an enabled optional surface.
